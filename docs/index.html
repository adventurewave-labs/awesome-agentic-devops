What is Agentic DevOps?

A synthesis of the definitions this list is built on:

Microsoft (Build 2025): AI-powered agents operating as members of dev and ops teams — Copilot agents plus Azure automating, optimizing, and accelerating the entire software lifecycle. Azure blog · Azure solution page

Opsera: The shift from static, human-managed scripts to autonomous agents that reason, self-correct, and manage the delivery pipeline — "autonomous decisioning across the software delivery lifecycle," not just autonomous execution. Combined with an AI-assisted upstream this becomes the AIDLC (AI Development Life Cycle). Opsera

Superagentic AI: A framework extending DevOps with autonomous agents capable of reasoning, decision-making, and adaptation — four pillars: automation→autonomy, intelligent orchestration, continuous learning, human-agent collaboration. super-agentic.ai

What it is NOT (per Opsera): not traditional CI/CD automation (deterministic vs. probabilistic), not just LLM code generation (no agency), and not AIOps (AIOps surfaces anomalies; agentic DevOps reasons through causes and executes remediation).

Protocols: MCP, A2A, AG-UI

The interoperability layer that made agentic DevOps practical (StackOne landscape framing: "MCP is how agents use tools. A2A is how agents collaborate.")

  • Model Context Protocol — the open standard for agent↔︎tool integration (now under the Linux Foundation).
  • modelcontextprotocol/servers ⭐91.3k — official reference server implementations.
  • modelcontextprotocol/python-sdk / typescript-sdk — official SDKs.
  • modelcontextprotocol/registry — community registry service for MCP servers.
  • Docker MCP Catalog & Toolkit — verified containerized MCP servers + gateway governance.
  • A2A (Agent2Agent protocol) · a2aproject/A2A ⭐26.2k — agent-to-agent interoperability, originally from Google, now Linux Foundation.
  • AG-UI — agent-to-user interaction protocol.

Safety First

Agentic DevOps agents can change infrastructure. Ground rules distilled from the sources above:

  1. Read-only or proposal mode first — gh-aw's staged: true, read-only MCP modes (K8s, DBHub, Flux), and approval gates before any write.
  2. Beware the "lethal trifecta" — private data + untrusted content (PRs, issues, web) + outbound access in one sandbox. GitHub's answer: six defense layers; yours should be at least one.
  3. Policy-as-code beats vibes — deterministic checks (OPA, protected approvals) must gate probabilistic agents; block terraform destroy-class actions outright.
  4. Scope credentials per agent — diagnosis agents get read-only; remediation agents get namespace-scoped writes; secrets via Doppler/Vault MCPs, never in prompts.
  5. Record everything — black-box recorder / compliance evidence packets for every production-adjacent run (see the OWASP MCP Top 10 and DevOpsAIguru123's safety model).
